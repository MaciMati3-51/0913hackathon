# 雰囲気ヒアリング設計（最大3問）

## 0. 解く問題

要件定義書は「自然言語を家電操作へ変換する」(7章) までは決まっているが、
**どこまで会話で詰めるか**が決まっていない。現状の実装は `generateScene(text)` の一発変換で、
会話は体験開始後の `adjustScene` だけ。つまり「雰囲気を一緒に決める」区間が存在しない。

ここを「起点=どんな雰囲気がいいか」「最大3問」で閉じる。

---

## 1. 原則：質問は家電の差分でしか価値を持たない

聞いていいのは、答えによって**デバイス設定値が実際に変わる**質問だけ。
値が変わらない質問は、ユーザーから見ると「聞かれただけ」になり、パーソナライズ感がむしろ落ちる。

よって軸は、家電の表現力から逆算して決める。

| 軸 | 値 | 動くデバイス | AIが推測できるか |
|---|---|---|---|
| `subject` 題材 | 海 / 夏祭り / … | visual, sound, aroma | ○ 自由文からほぼ取れる |
| `time` 時間帯 | day / sunset / night | visual, light.brightness, light.color | △ 見た目の変化が最大 |
| `density` 人の気配 | quiet / lively | sound mix, aroma, brightness微調整 | △ 好みが割れる |
| `body` 体感 | cool / mild | **temperature, fan** | ✕ 個人差。推測不可 |

`location` `season` `era` は聞かない。自由文から取れれば使い、取れなければ既定値（湘南・夏・2026）。
ここを聞くと3問がすぐ埋まるのに、家電の値はほとんど動かない。

**`body` だけは原則必ず聞く。** 唯一AIが当てられない軸で、かつエアコンと扇風機という
「動画視聴との差別化」(19章) の核が動く軸だから。

---

## 2. フロー

```
Q1  固定・自由入力  「どんな雰囲気の中にいたい？」＋ 候補チップ4つ
      ↓ 自由文からスロット抽出（チップは事前にスロットをタグ付け済み＝1タップで2〜3軸確定）
Q2  動的・2〜3択    未確定スロットのうち「デバイス差分が最大」の軸を1つ
      ↓
Q3  動的・2択       残りの未確定軸。多くの場合 body
      ↓
要約1行 → シーン確認画面（13.2）→ 体験開始
```

### 打ち切り規則
- Q1 で `subject` `time` `density` が埋まったら、Q2 は `body` のみ聞いて**2問で終了**。
- 3問使っても埋まらない軸は既定値で埋め、聞かない。「AIが決めた」と明示する。
- 早く終わること自体が価値（「もう分かった」の演出）。デモ台本では3問通す。

### Q1 チップ（タップで複数スロットが同時に埋まる）

| チップ | 埋まるスロット |
|---|---|
| ひとりで静かに海を見たい | subject=beach, density=quiet |
| 友達と賑やかに | density=lively, time=day |
| 夕暮れをぼーっと眺めたい | time=sunset, density=quiet |
| 夜風にあたりたい | time=night, body=cool |

### Q2/Q3 の質問テーブル（固定文言・固定選択肢）

**time**
> 空はどのくらいの時間？

| 選択肢 | 家電プレビュー |
|---|---|
| まだ明るい昼 | 照明 60% / 白色 |
| 陽が落ちる夕方 | 照明 20% / 暖色 |
| もう暗い夜 | 照明 8% / 暖色 |

**density**
> まわりに人はいてほしい？

| 選択肢 | 家電プレビュー |
|---|---|
| 波の音だけ | 音：波・海風 |
| 遠くに人の声 | 音：波・海風・人の声 |

**body**
> 体はどうしたい？

| 選択肢 | 家電プレビュー |
|---|---|
| 涼しく、風を感じたい | エアコン 24℃ / 扇風機 中 |
| ぬるい夏の空気のまま | エアコン 27℃ / 扇風機 弱 |

**選択肢には必ず家電の変化値を添えて表示する。** これが「AIが家電を操作している」ことの
唯一の可視化であり、デモの見せ場。抽象語だけの選択肢にはしない。

### 合流の1行

3問の答えを1文に畳んで見せる。

> 「人のいない夕暮れの海で、涼しい風にあたる」でいい？

3つの答えが1つの雰囲気に合流したことを示す。これがユーザーの体感する
パーソナライズであって、質問数ではない。

---

## 3. パーソナライズをどこまでやるか（層を2つに分ける）

| 層 | 内容 | 保存 | 質問 |
|---|---|---|---|
| **層1 体質** | 寒がり/暑がり、暗め好き、静か好き | する（localStorage / KV） | 2回目以降は聞かない |
| **層2 今日の気分** | 時間帯、賑やかさ、題材 | しない | 毎回聞く |

**3問という設計は「層2だけ聞く」状態。** 層1が貯まると質問は2問→1問に減る。
初回3問 / 2回目以降2問、という**減っていく**挙動そのものが、
要件21章 Phase 5「Season Agent」への橋になる。プレゼンで言える。

層1を層2に混ぜて毎回聞くと、ユーザーは「同じことを何度も聞かれる」と感じる。ここが分割の理由。

## 4. 実装

### エンドポイント

`POST /api/interview` （新規）

```jsonc
// request
{
  "state": { "turn": 1, "slots": { "subject": "beach", "density": "quiet" } },
  "answer": "夕暮れをぼーっと眺めたい"   // 自由文 or チップID
}

// response（質問継続）
{
  "state": { "turn": 2, "slots": { "subject": "beach", "density": "quiet", "time": "sunset" } },
  "done": false,
  "question": {
    "axis": "body",
    "text": "体はどうしたい？",
    "options": [
      { "id": "cool", "label": "涼しく、風を感じたい", "preview": { "temperature": 24, "fan": "medium" } },
      { "id": "mild", "label": "ぬるい夏の空気のまま", "preview": { "temperature": 27, "fan": "low" } }
    ]
  }
}

// response（完了）
{ "state": {...}, "done": true, "summary": "人のいない夕暮れの海で、涼しい風にあたる", "scene": { /* 既存のscene JSON */ } }
```

state はクライアント保持。KV不要。

### LLMにやらせること／やらせないこと

| | 担当 |
|---|---|
| 自由文 → スロット抽出 | **LLM**（JSON schema, strict） |
| 次に聞く軸の選択 | コード（未確定軸の優先度テーブル順） |
| 質問文・選択肢・プレビュー値 | **コード（固定テーブル）** |
| 最後の1行要約 | **LLM** |
| スロット → scene JSON | 既存 `generateScene()` に合成文を渡して再利用 |

質問文と選択肢をLLMに毎回生成させない理由は3つ。

1. **レイテンシ** — 要件14.2の応答速度に、1問ごとのLLM往復は入らない
2. **ブレ** — デモで毎回違う質問が出ると台本が崩れる
3. **嘘の防止** — プレビューの家電値をLLMが書くと、実際の scene と食い違う

抽出だけなら `gpt-4.1-mini` で1〜2秒。既存の `withFallback` と同じくタイムアウト時は
スロット未確定のまま次の固定質問へ進めばよく、体験は壊れない。

### スロット → 合成文

```js
const text = `${slots.era ?? '2026年'}${slots.season === 'summer' ? '8月' : ''}の` +
             `${TIME_JA[slots.time]}の${slots.location ?? '湘南'}の海。` +
             `${DENSITY_JA[slots.density]}。${BODY_JA[slots.body]}。`;
// → 既存の generateScene(text, env) にそのまま渡す
```

`lib/llm.js` を書き換えずに済む。ハッカソンの改修量が最小。

## 5. 先に潰す矛盾：素材が1つしかない

`lib/llm.js` の `VISUALS = ['shonan_sunset']` / `SOUNDS = ['ocean_wave']`。
このまま `time` を聞くと、**「昼」と答えても映像が変わらない**。原則1に反し、質問が嘘になる。

どちらかを先にやる。

- **A（推奨・安い）** 映像は1本のまま、`time` を CSS フィルタで表現する。
  空の色・彩度・明度を `day / sunset / night` で切り替え、照明UIと連動させる。
  「同じ海が時間で変わる」ので10章の時間変化演出にもそのまま使える。
- **B** `shonan_day` / `shonan_night` の素材を追加し、`VISUALS` を広げる。

`density` は `ocean_wave` に人声トラックを重ねるだけなので、音声レイヤーを2本に分ければ済む。
